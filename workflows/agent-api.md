# 接口模式的整理方案

本次没有文件工具，也不执行命令。前面的整理规则只用于判断内容；全部资料已随消息提供。
应用会检查方案，并只保存本机笔记和当前用户档案允许修改的两节。

只输出一个 JSON 对象，不要代码围栏：

```json
{
  "notes": [
    {
      "file": "example.md",
      "note": {
        "title": "标题",
        "triggers": ["phoneme:l"],
        "words": [],
        "contrasts": [],
        "body": "## 自检法\n具体动作。\n## 对比训练\n先中文对照，再英文练习。"
      }
    }
  ],
  "profile": { "confirmed": "这一节的新正文", "watching": "这一节的新正文" },
  "summary": "改了什么，以及依据"
}
```

- `notes` 必须提供，没有改动时为 `[]`；每项是笔记的完整新内容。`summary` 必填（最长 2000 字）；顶层只放 `notes` / `profile` / `summary`。
- 规模上限：`notes` 最多 50 项，`title` ≤200 字、`body` ≤4 万字，`triggers` / `words` / `contrasts` 各 ≤64 项、每项 ≤120 字；`file` ≤180 字；档案每一节 ≤1.2 万字；整份回复原文 ≤20 万字。超限会被整批拒绝。
- 修改已有本机笔记时，`file` 必须与资料中的文件名完全一致。不要写路径。
- 新笔记用小写字母、数字和连字符命名，以 `.md` 结尾；ID、YAML 元数据由应用生成。
- 只有确需删除已有本机笔记时，才使用 `{"file":"原文件.md","note":null}`。
- 随附参考笔记不能删除或直接修改；需要补充时新建本机笔记。
- `profile` 可省略，两个字段也可分别省略；只填对应小节的新正文，不带章节标题或 AUTO 标记。
- 不改变个人断言的证据门槛。没有足够证据时，保持原状，不为完成任务硬改。
- 正文中的引号、换行必须按 JSON 转义。所有数组元素都是字符串。
